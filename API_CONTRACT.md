# Контракт API

Ключевой документ связки двух дисциплин. Фиксируется на вехе 1 и далее меняется только по согласованию внутри команды.

---

## Зачем он нужен

Модель будет готова в середине ноября. Сервис вокруг неё начинают делать в конце сентября. Разрыв в полтора месяца закрывается контрактом: команда заранее договаривается, **что принимает и что возвращает** сервис, и веб-часть развивается против этой договорённости, не дожидаясь модели.

Из этого следует главное свойство связки: **ни одна из дисциплин не зависит от результата другой**. Сайт работает с заглушкой и оценивается полным баллом. Модель защищается по метрикам и оценивается без демонстрации сайта.

---

## Что фиксируется

1. **Адрес эндпоинта** — `/analyze`, `/extract`, `/search`, `/transform`.
2. **Метод** — как правило, POST.
3. **Формат запроса** — какие поля, каких типов, какие обязательны.
4. **Формат ответа** — какие поля, каких типов.
5. **Поведение при ошибке** — что возвращается при пустом вводе, слишком длинном тексте, неверном формате.
6. **Ограничения** — максимальная длина текста, число запросов.

## Типовые контракты по трекам

### Трек А. Классификация

```json
POST /analyze
Запрос:
{ "text": "строка", "lang": "ru" }

Ответ:
{
  "label": "positive",
  "score": 0.87,
  "all_scores": { "positive": 0.87, "neutral": 0.09, "negative": 0.04 },
  "keywords": ["отлично", "рекомендую"]
}
```

Поле `keywords` — слова, повлиявшие на решение. Оно необязательно, но делает интерфейс намного содержательнее: пользователь видит не только вердикт, но и его основание.

### Трек Б. Извлечение сущностей

```json
POST /extract
Запрос:
{ "text": "строка" }

Ответ:
{
  "entities": [
    { "text": "Пушкин", "type": "PER", "start": 0, "end": 6, "score": 0.95 },
    { "text": "Петербург", "type": "LOC", "start": 15, "end": 24, "score": 0.91 }
  ]
}
```

Поля `start` и `end` обязательны: без них интерфейс не сможет подсветить сущности в исходном тексте.

### Трек В. Семантический поиск

```json
POST /search
Запрос:
{ "query": "строка", "top_k": 5 }

Ответ:
{
  "results": [
    { "id": "doc_42", "text": "фрагмент", "score": 0.81, "source": "название источника" }
  ],
  "total_found": 17
}
```

### Трек Г. Преобразование текста

```json
POST /transform
Запрос:
{ "text": "строка", "mode": "simplify" }

Ответ:
{
  "original": "исходный текст",
  "result": "преобразованный текст",
  "changes": [ { "from": "осуществлять контроль", "to": "проверять" } ]
}
```

Поле `changes` позволяет интерфейсу показать, что именно изменилось.

## Ошибки

Единый для всех треков формат:

```json
{ "error": "text_too_long", "message": "Текст длиннее 5000 знаков", "limit": 5000 }
```

Минимальный набор ситуаций, которые контракт обязан покрывать:

| Ситуация | Код | HTTP |
|---|---|---|
| Пустой текст | `empty_text` | 400 |
| Текст длиннее допустимого | `text_too_long` | 400 |
| Неподдерживаемый язык | `unsupported_language` | 400 |
| Модель не загрузилась | `model_unavailable` | 503 |

## Заглушка

Пишется на паре 5 веб-программирования, работает до конца ноября.

```python
from fastapi import FastAPI
from pydantic import BaseModel
import random

app = FastAPI()

class TextIn(BaseModel):
    text: str
    lang: str = "ru"

@app.post("/analyze")
def analyze(item: TextIn):
    if not item.text.strip():
        return {"error": "empty_text", "message": "Введите текст"}
    if len(item.text) > 5000:
        return {"error": "text_too_long", "message": "Текст длиннее 5000 знаков", "limit": 5000}

    # ЗАГЛУШКА. Будет заменена на вызов модели в конце ноября.
    labels = ["positive", "neutral", "negative"]
    label = random.choice(labels)
    return {
        "label": label,
        "score": round(random.uniform(0.6, 0.99), 2),
        "keywords": item.text.split()[:3],
    }
```

**Правила заглушки:**

- возвращает данные **той же формы**, что вернёт реальная модель;
- обрабатывает ошибочные случаи так же, как будет обрабатывать реальная;
- помечена комментарием, чтобы её не забыли заменить;
- находится в отдельной функции, чтобы замена была правкой в одном месте.

## Замена заглушки на модель

Происходит после вехи 2, на паре 19 веб-программирования (25.11 у гр. 1, 03.12 у гр. 2).

```python
from model import predict   # ваша модель

@app.post("/analyze")
def analyze(item: TextIn):
    if not item.text.strip():
        return {"error": "empty_text", "message": "Введите текст"}
    if len(item.text) > 5000:
        return {"error": "text_too_long", "message": "Текст длиннее 5000 знаков", "limit": 5000}

    return predict(item.text)
```

Если контракт не менялся, интерфейс переписывать не нужно вообще.

**Что готовит NLP-часть к передаче:**

1. Функция `predict(text)`, возвращающая словарь ровно по контракту.
2. Файл с весами модели или её имя на HuggingFace.
3. Строка в `requirements.txt` со всеми зависимостями.
4. Время работы на одном тексте — чтобы веб-часть понимала, нужен ли индикатор загрузки.
5. Что функция возвращает на пустом и на очень длинном вводе.

## Изменение контракта

Контракт можно менять — часто случается так, что первоначальное представление о задаче было неточным. Порядок:

1. Тот, кто хочет изменить, пишет, что и почему меняется.
2. Изменение согласуется всей командой.
3. Правится этот файл, старая версия остаётся в истории репозитория.
4. Обновляется заглушка.

**Изменение контракта после 17 ноября требует обоснования на паре.** К этому моменту интерфейс уже написан, и правка означает переделку веб-части в последние недели семестра.

## Где будет работать сервис

Модель нельзя опубликовать на Netlify — он раздаёт только статику. Варианты:

| Способ | Когда подходит |
|---|---|
| **ngrok** | Демонстрация на защите. Временная публичная ссылка на локальный сервер. Упомянут в РПД по вебу |
| **HuggingFace Spaces** | Постоянная демонстрационная версия, бесплатно, модель рядом с сервисом |
| **Локальный запуск** | Запасной вариант: показ с ноутбука на защите |

Решение принимается заранее.
