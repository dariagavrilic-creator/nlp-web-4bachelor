# Темы ИОГВ для семестрового проекта: АОЕЯ + Web

Темы из сводного перечня исполнительных органов власти Санкт-Петербурга (Приложение 4), пригодные для **командного проекта 4 курса бакалавриата** в связке двух дисциплин: «Автоматическая обработка естественного языка» и «Основы Web программирования».

**Номера тем сохранены оригинальные.**

---

## Условия отбора

Тема попала в этот файл, если выполняются все четыре условия:

1. Задача сводится к функции **текст на входе → структура на выходе** — иначе её нельзя обернуть в сервис.
2. Данные доступны из открытых источников. Ведомственный материал за семестр получить нельзя.
3. Реализуема командой из 2–3 человек за 7–8 пар АОЕЯ.
4. Даёт содержательный интерфейс: сайт должен показывать больше, чем одно слово в ответ.

---

## Чем это отличается от ВКР

**Это не ВКР и не выполнение заказа ИОГВ.** Семестровый проект — учебный прототип, демонстрирующий подход на открытых данных. Заказчику он не сдаётся и обязательств не создаёт.

Ценность связи с перечнем в другом: студент работает над задачей, которая реально кому-то нужна, а не придумана для учебного упражнения. Это заметно влияет на вовлечённость. Кроме того, удачный семестровый проект — естественный задел для ВКР следующего года по той же теме, но уже с ведомственными данными.

**Что сказать студентам:** «Эти задачи поставлены городскими ведомствами. Мы делаем прототип на открытых данных — не для сдачи заказчику, а чтобы разобраться, как такие задачи устроены. Если тема понравится, на четвёртом курсе из неё получается диплом».

---

## Как устроено описание

У каждой темы:

- **Задача** — что делает функция;
- **Контракт** — заготовка API, с которой веб-часть начинает работать в сентябре;
- **Данные** — открытый источник;
- **Минимальная версия** — что работает при любом развитии событий;
- **На сайте** — что показывает интерфейс;
- **Трек** — по классификации репозитория `nlp-web-4bachelor`;
- **Сложность**.

# Тема 15-А. Классификатор обращений граждан

**Исходная тема ИОГВ №15:** Разработка интеллектуальной системы анализа обращений граждан по вопросам образования
**Заказчик:** Администрация Московского района
**Трек:** А — классификация · **Сложность:** низкая

**Задача.** Определяет тематику обращения и его характер: жалоба, запрос сведений, предложение, заявление.

**Контракт**

```json
POST /analyze
Запрос:  { "text": "строка", "lang": "ru" }
Ответ:
{
  "topic": "приём в школу",
  "type": "жалоба",
  "urgency": "высокая",
  "score": 0.88,
  "all_topics": { "приём в школу": 0.88, "питание": 0.07, "перевод": 0.05 },
  "keywords": ["отказали", "не по прописке", "первый класс"]
}
```

**Данные.** Обращения на портале «Наш Санкт-Петербург», открытые группы районных администраций, разделы «вопрос-ответ» на сайтах комитетов. Категория выводится из раздела, куда обращение отнесено.

**Минимальная версия.** Пять тематик, вердикт с уверенностью.

**На сайте.** Поле ввода обращения, вердикт с распределением по темам, подсветка слов, повлиявших на решение, подсказка «куда обращаться с этим вопросом».

**Почему тема удачная.** Разметка следует из источника, данных много, интерфейс наглядный. Хороший выбор для команды, которой важно гарантированно доделать.

# Тема 14. Вопросно-ответная система по правам на образование

**Исходная тема ИОГВ №14:** Создание системы автоматизированной поддержки граждан по вопросам реализации прав на образование с применением ИИ
**Заказчик:** Администрация Московского района
**Трек:** В — семантический поиск · **Сложность:** средняя

**Задача.** По вопросу гражданина находит релевантный пункт нормативного акта и формулирует ответ со ссылкой на источник.

**Контракт**

```json
POST /ask
Запрос:  { "question": "строка" }
Ответ:
{
  "answer": "краткий ответ",
  "sources": [
    { "document": "ФЗ Об образовании", "article": "ст. 67 ч. 3", "text": "цитата пункта" }
  ],
  "confidence": 0.79,
  "matched_terms": { "не по прописке": "не проживающие на закреплённой территории" }
}
```

Поле `matched_terms` — самое интересное. Оно показывает, как обыденная формулировка вопроса была сопоставлена с юридической формулировкой документа. Для интерфейса это ценный элемент: пользователь видит, как его вопрос был понят.

**Данные.** Нормативные акты об образовании — открыты полностью. Типовые вопросы — разделы «вопрос-ответ», форумы родителей.

**Минимальная версия.** Поиск релевантного пункта без порождения ответа. Уже полезно и уже работает.

**На сайте.** Поле вопроса, ответ, **обязательная** ссылка на пункт документа с раскрывающейся цитатой, словарь соответствий «как вы спросили — как это называется в законе».

**Обязательное условие.** Ответ без ссылки на источник не засчитывается. Это оговаривается при выборе темы: система, порождающая правдоподобные утверждения о правах граждан без указания документа, вредна.

# Тема 21. Структурирование распознанного архивного текста

**Исходная тема ИОГВ №21:** Автоматическое распознавание и структурирование текста исторических документов
**Заказчик:** Архивный комитет
**Трек:** Б — извлечение сущностей · **Сложность:** средняя

**Задача.** Принимает сырой текст после распознавания, исправляет типичные ошибки и извлекает структуру документа.

**Контракт**

```json
POST /extract
Запрос:  { "text": "сырой текст после OCR", "normalize_orthography": true }
Ответ:
{
  "cleaned_text": "исправленный текст",
  "corrections": [
    { "from": "нзвѣстно", "to": "известно", "type": "ocr_error", "position": 45 }
  ],
  "structure": {
    "doc_type": "прошение",
    "date": "1913-04-12",
    "addressee": "Городская управа",
    "author": "Иванов И. И."
  },
  "entities": [ { "text": "Васильевский остров", "type": "LOC", "start": 210, "end": 229 } ]
}
```

**Важно для контракта.** На вход подаётся **текст**, а не изображение. Распознавание выполняется до вызова сервиса готовой библиотекой. Это сохраняет форму «текст → структура» и оставляет проект в границах курса.

**Данные.** Открытые архивные коллекции. Сырые результаты распознавания получаются готовыми библиотеками на сканах.

**Минимальная версия.** Исправление частых ошибок распознавания плюс извлечение даты и типа документа.

**На сайте.** Скан и распознанный текст рядом, подсветка исправлений, извлечённая карточка документа, экспорт в структурированный формат.

**Почему тема сильная.** Это единственная тема в списке, где содержание работы прямо совпадает с профилем направления: перевод, терминология, локализация. Она же лучше всех продолжается в ВКР магистратуры.

```json
  "disclaimer": "Инструмент выявляет языковые признаки, а не устанавливает достоверность сведений"
}
```

**Существенное ограничение.** Работа ведётся **только на обычном материале**: реклама, коммерческие рассылки, кликбейт-заголовки, мошеннические сообщения из открытых баз предупреждения граждан. Сбор и анализ материалов экстремистского содержания в проект не входит и темой не предполагается.

**Данные.** Рекламные тексты, новостные заголовки, примеры мошеннических сообщений, публикуемые банками и ведомствами для информирования граждан.

**Минимальная версия.** Три типа приёмов с подсветкой.

**На сайте.** Текст с подсветкой найденных приёмов, объяснение каждого при наведении, обучающий режим с разбором примеров.

**Обязательное условие.** Оговорка в интерфейсе о том, что инструмент показывает языковые признаки, а не оценивает истинность содержания.
